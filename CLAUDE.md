# Applied AI Hub - project rules

A static PWA that ranks new applied-AI videos (YouTube) and lists recent posts
(RSS/Atom) across a Home page and 11 sections. Hosted on GitHub Pages at `/applied-ai-hub/`.
Modelled on the sibling `news-hub` project: same folder layout, same
serverless data flow, no backend.

## Data flow

```
GitHub `schedule` (4x/day) -> scripts/fetch.py          -> data/videos.json
                           -> scripts/fetch_written.py  -> data/posts.json
                           -> git commit + push -> GitHub Pages -> static pages read data/*.json
```

## Source of truth

- `data/portal_sources.csv` is the ONLY place channels and feeds are defined.
  `scripts/channels.py` reads it and groups rows by the `track` column - one
  section per track. Do not hardcode channel IDs anywhere else.
- Section metadata (slug, title, icon, colour, blurb) lives in `data/sections.json`
  (loaded and validated by `scripts/channels.py`). A CSV row whose `track` is not
  in that file makes the
  import fail on purpose - add the section, do not loosen the check.
- `layer` is Primary (official/first-party), Analysis, or Practitioner. Keep
  the three values; the Layer filter on every page depends on them.

## Generated files - never edit by hand

- `index.html` (landing page: tile grid of every page, `LANDING` in `channels.py`),
  `all.html` (merges every section; slug `all`, defined as `HOME` in `channels.py`)
  and the eleven section pages (`oracle`, `news`, `agents`, `coding`,
  `engineering`, `enterprise`, `productivity`, `business`, `video`, `selfhost`,
  `marketing` `.html`) are generated by `python scripts/build_pages.py` (run by the workflow).
  Change `scripts/build_pages.py` or `assets/hub.css|hub.js`, rebuild, and
  commit the output.
- `data/videos.json`, `data/posts.json`, `data/channels_meta.json`,
  `data/video_id_cache.json`, `data/periodic_state.json` are written by the
  fetchers/workflow. Do not hand-edit them.
- `icons/*.png` come from `scripts/create_icons.py` (stdlib only, no Pillow).

## Adding or removing a section

Data only, no code: add/remove the entry in `data/sections.json` and its rows in
the CSV, and commit. The workflow (`refresh.yml`) runs `scripts/build_pages.py`
on every run and on any push touching the CSV, `sections.json`, `build_pages.py`
or `channels.py`; it generates the new page and deletes the page of a removed
section. No `sw.js` change is needed (section pages are cached as visited). The
workflow commits the generated HTML, so never hand-edit it.

## Fetcher rules

- YouTube quota is 10,000 units/day. Discover videos with `playlistItems.list`
  on the uploads playlist (1 unit), never `search.list` (100 units). Batch
  `videos.list` 50 IDs at a time. Do not add per-video or per-channel calls.
- Videos under 60 s (Shorts) are dropped by `MIN_DURATION`. The ranking window is
  `FETCH_DAYS` (90) for every section (a section can override it with `window_days`
  in `SECTIONS`). The cache purge, stats refresh, playlist scan and `keep()` all go
  through `window_seconds(section)` - change the constant, not individual cutoffs.
  The pages' Time filter (1d/3d/7d/30d/90d, default 7d) is just a view over this.
- A section can set `title_filter` (see `TITLE_FILTERS` in `channels.py`); videos
  failing it are dropped and cached as dropped so they are never re-fetched.
  Oracle AI uses this to keep only AI videos. Changing the window or a section's
  filter needs its channels removed from `data/video_id_cache.json` and
  `last_scan` once (or clear both), so the next run backfills.
- A failed run must carry existing data forward, never blank a section
  (`fetch.py` merges into the previous output; `fetch_written.py` carries a
  failed feed's old posts). Preserve that when changing either script.
- `fetch_written.py` uses only the standard library; keep `requirements.txt` to
  `google-api-python-client` and `python-dotenv`.
- `YOUTUBE_API_KEY` comes from `.env` locally and the repo secret in Actions.
  Never commit `.env` or print the key.

## Frontend rules

- Vanilla HTML/CSS/JS only: no framework, no bundler, no build step beyond
  `build_pages.py`.
- Everything read from `data/*.json` (titles, channel names, links) is
  untrusted. It must pass through `esc()` before reaching `innerHTML`, and
  links through `safeUrl()`. Never put titles in inline `onclick` strings.
- Keep pages usable at phone width; this is installed as a PWA.
- If you rename or add a precached file listed in `sw.js`, bump `CACHE_NAME`.
- `manifest.json` and `sw.js` hardcode the `/applied-ai-hub/` base path; keep
  them in sync if the repo is renamed.

## Topics tab

- The logic lives in `assets/topics.js`: pure functions with no DOM access, loaded
  by the pages as `window.HubTopics` and by Node for `scripts/test_topics.js`. Keep
  it DOM-free so it stays testable.
- When topics look wrong, tune the word lists in that file (`STOP` filler,
  `GENERIC` section words, `COMMON_EXTRA` ordinary words) and check with
  `node scripts/test_topics.js <section> <days> rising|mentions` on the real
  data before touching the UI. Do not add per-section hacks in `hub.js`.
- Tuning that does not need code goes in `data/topic_rules.json` (`ignore_words`,
  `ignore_topics`, `aliases`); prefer that over editing the word lists. The
  workflow runs `scripts/check_topics.js` after each refresh as a smoke test; keep
  it dependency-free (Node standard library only) so it runs in Actions untouched.
- Each toolbar control in `build_pages.py` lists the tabs it applies to in
  `data-tabs`; add the new tab name there when adding a tab.

## Shorts viewer

- `assets/shorts.js` (`window.ShortsViewer`) is the swipe viewer; `hub.js` opens it
  only from the Shorts tab, passing the filtered list. Its markup lives in the
  `build_pages.py` template (`#shortsViewer`), styles in `hub.css` (`.sv-*`).
- Never change the video by assigning `iframe.src`: it adds browser-history
  entries and breaks the Back button. `loadFrame()` replaces the element instead.
- Keep touch handling on the transparent `#svGesture` layer (pointer events,
  `touch-action: none`): the YouTube iframe underneath swallows touches.
- Changes were tested with Playwright (phone touch swipes, mouse drag, wheel, keys,
  Back, every page); keep that behaviour when editing.

## Commands

```bash
pip install -r requirements.txt
python scripts/fetch.py            # needs YOUTUBE_API_KEY
python scripts/fetch_written.py    # no key needed
python scripts/build_pages.py
python scripts/create_icons.py
python -m http.server 8000         # then open http://localhost:8000
```
